# CommunityOS — Hackathon Demo Strategy

## Demo Narrative

The demo should tell this story in sequence:

1. **Community generates activity** — events happen, questions are asked, resources are shared, code is contributed
2. **CommunityOS ingests and structures** — raw activity becomes connected knowledge (Memory)
3. **Radar analyzes the trajectory** — gaps, strengths, and emerging trends are detected
4. **Insights are explained** — each insight shows evidence, confidence, contributing data
5. **Recommendations are actionable** — the system suggests what to do next (event, workshop, connection, resource)
6. **Connect surfaces the right people** — expertise matching grounded in real activity

## Hero Moments

### Radar Dashboard (Must Have)
- Visual display of community knowledge landscape
- Clear gap cards showing demand vs. expertise mismatch
- Emerging trend indicators with trajectory visualization
- Strength areas with evidence
- Each insight card showing: what, why, confidence, suggested action, supporting data

### Evidence Trail (Must Have)
- Click into any Radar insight and see the underlying data
- "This gap was detected from 14 unanswered questions across 3 events and 2 Discord channels"
- Named members, specific events, timestamped activity

### Recommendation Engine (Should Have)
- "Schedule a RAG Evaluation workshop — 18 members interested, Elena Rostova (98% match) available as speaker"
- Grounded in actual community data, not generic suggestions

### Knowledge Ingestion (Should Have)
- Show how raw community data (event transcript, Q&A log, GitHub activity) becomes structured intelligence
- Demonstrate the pipeline: raw → extracted → classified → connected → scored

## Visual Standards for Demo

- Dark AWS-themed interface creates a professional, technical feel
- Data-dense layouts that feel like a real operations console
- Monospace labels and uppercase section headers convey precision
- Orange/blue semantic coloring immediately communicates gap vs. strength
- Trajectory sparklines or charts show time-based trends
- Confidence scores shown as percentages or visual indicators

## What Makes a Good Demo Feature

Ask these questions:
- Does it show intelligence, not just data display?
- Does it demonstrate that CommunityOS understands the community?
- Can the audience see evidence behind the insight?
- Does it feel different from a generic dashboard?
- Would a community organizer immediately see value?

## Demo Flow (Suggested Order)

1. **Open** — Show the Organizer dashboard with Radar view
2. **Explore a gap** — Click into "Production RAG Evaluation" gap, show evidence
3. **See the recommendation** — System suggests a workshop with matched speakers
4. **Show trajectory** — Topic demand growing over 6 data points
5. **Switch to Learner** — Ask a question, get matched with a relevant Pro
6. **Show the Pro** — Their expertise is evidenced by past contributions, not just self-reported skills
7. **Close** — Return to Radar, show the full landscape of community intelligence

## Anti-Patterns for Demo

- Showing raw CRUD forms (create event, add member) — boring
- Generic search results without intelligence — undifferentiated
- AI outputs without source attribution — untrustworthy
- Features that require explanation to understand — should be self-evident
- Slow loading or broken states — kills credibility
